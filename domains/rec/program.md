## 铁律(不可谈判)

1. **只改 `model.py`**。`prepare.py` / `judge.py` / `delivery.py` 是冻结装置,`program.md` 只归人类。
2. **固定预算**:单实验训练耗时 ≤ 60s(护栏 `train_seconds`),超时判 failed,不争论。
3. **单一主指标**:只认 AUC(方向 max),`val_logloss ≤ 0.35` 是护栏。指标在域契约 `domain.json` 里,循环中不可修改。
4. **双门禁,棘轮只进不退**:
   - 第一道(离线棘轮):AUC 提升 ≥ min_delta(基线方差自适应)才候选保留;
   - 第二道(交付门禁):候选还要在端到端交付仿真(`delivery.py`)里验证——
     交付主指标 `session_ctr` **不回退**、生态护栏(曝光品类熵 `coverage_entropy`、
     冷启用户 CTR `cold_user_ctr`)不破,才算真正保留。
   - **离线涨但被交付门禁拦下 = 组织最贵的教训**,自动记入失败库(带离线-交付兑现率)。
5. **单一变量原则**:每轮实验只推进一件事,便于归因。
6. **诚实报告**:meta 里如实上报生效 knobs;不做任何针对评测集的过拟合(内部验证集与 val 已分离,数据指纹会校验)。

## 三道关(体系全景)

```
离线棘轮(秒级,高吞吐)──► 交付门禁(端到端会话仿真)──► 上线门禁(永远在人类手里)
     走得快                      走得对                     定边界
```

研究员必读:离线 AUC 是代理,交付 CTR 才是业务。查阅台账里的 `alignment`
字段(离线 Δ / 交付 Δ / 兑现率),优先提出历史上**兑现率高**的方向;
任何让曝光生态向热门坍缩(马太效应)的改动,离线再涨也过不了交付门禁。

## 迭代策略建议(研究员必读)

- 先读台账:**失败库 = 避坑地图,策略库 = 已验证的有效方向**。不要重复试已失败的方向。
- 优先级经验:特征交叉类改动 > 收敛类改动(epochs/lr)> 正则类 > 校准类(校准不动 AUC,注定被棘轮拒绝——除非某天主指标换成 logloss)。
- 累积式改进:每次基于当前最优(elite)叠加,不要整体推翻。
- 大胆假设,小心求证:激进想法可以做,但预期会失败时在 rationale 里写明,失败后把教训写清楚。

- 避坑:台账中已有 2 次类似失败(「auc 0.626532 未超过 elite 0...」),同类想法需先论证差异
- 避坑:任何让曝光生态向热门坍缩的改动,即使离线与交付 CTR 双涨,也会被曝光熵护栏拦下(见台账 rejected_by_delivery)
## 评测协议

- 数据:`data/train.npz`(2 万曝光)+ `data/val.npz`(5 千曝光),seed 固定,数据指纹在 `data/manifest.json`。

- 指标:`metrics.auc`(主)、`metrics.val_logloss`(护栏)、`guards.train_seconds`(护栏)。

## 与自动驾驶等级的关系

- **L2(辅助)**:人类逐个审核本组织产出的 patch(看 experiments 台账里的 knobs/diff);
- **L3(有条件自动)**:本文件生效,组织在离线装置上全自动循环,人类只审"上线门禁";
- **L4(高度自动)**:多分支并行 + elite 定期复验,人类只读晨报;
- **L5(通用)**:同一引擎接入 domains/search、domains/ads —— 组织能力与业务域解耦。

你现在的默认工作等级是 **L3**。开工。
