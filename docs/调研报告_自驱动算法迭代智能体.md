> 本报告是 AlgoPilot 项目的设计依据。项目定位:**像自动驾驶一样的智能组织通用迭代能力,先在搜广推算法域落地。**

## 一、主参考:Karpathy autoresearch(2026-03)

仓库:[karpathy/autoresearch](https://github.com/karpathy/autoresearch) · 单 GPU nanochat 训练 · 630 行代码

### 1.1 核心理念

> "你不再像研究者一样改任何 Python 文件。你编程的是 `program.md` —— 它给 AI agent 提供上下文、搭建你的自主研究组织(research org)。"

一句话:**人类编写"组织代码"(program.md),AI 在固定的实验装置里自主迭代代码,用不可博弈的单一指标做棘轮(ratchet)。**

### 1.2 三文件铁律

| 文件 | 角色 | 谁可以改 |
|---|---|---|
| `prepare.py` | 固定常量、一次性数据准备、评测工具 | **谁都不许改**(实验装置) |
| `train.py` | 完整模型+优化器+训练循环,一切皆可改(架构/超参/优化器/batch) | **只有 agent 改**(唯一可编辑文件) |
| `program.md` | 组织指令:研究方向、实验规则、判据 | **只有人类改**(组织代码) |

### 1.3 Ratchet Loop(棘轮循环)

```
读 program.md → 修改 train.py(每次 1~2 处)→ 固定 5 分钟训练
→ 算 val_bpb(越低越好)→ 更低:保留为新基线;变高:放弃,回退到最优版本
→ 重复(约 12 次/小时,睡一晚 ≈ 100 次实验)
```

三条不可博弈的规则,是整个循环可信的根基:

1. **固定时间预算**:每次实验纯训练 5 分钟(墙钟,不含启动/编译)。这让"改模型大小/改 batch"等所有改动直接可比,且实验结果自动适配你的硬件。
2. **单一指标**:val_bpb,与词表大小无关,不可被"换个指标好看"钻空子。
3. **棘轮只进不退**:改进才保留,否则回退。失败的实验不是浪费——它们是"避坑经验"(灰色点)。

### 1.4 对本项目的启示

- **不要造复杂框架,要造"实验装置"**:630 行里没有任何 agent 框架,循环的执行者是外部编码智能体(Claude Code 等),repo 只提供铁律与判据。
- **program.md 是一等公民**:换研究方向 = 改一个 markdown。迭代"迭代能力本身"的最小成本路径。
- **单文件可改**保证 diff 可审查,这是把"自主"关进笼子的关键。

## 三、理念框架:算法迭代的自动驾驶等级

把自动驾驶分级移植到搜广推算法迭代(这是 AlgoPilot 的路线图骨架):

| 等级 | 类比 | 含义 | 人在回路 |
|---|---|---|---|
| **L0** | 全人工 | 算法工程师手写代码、手跑实验、手写周报 | 全程 |
| **L1** | 定速巡航 | 自动跑评测/出报表,人改代码 | 人改码,机器评测 |
| **L2** | 辅助驾驶 | Agent 提假设+写 patch+跑评测,**人审核合并** | 审每个 patch |
| **L3** | 有条件自动 | 离线 bench 范围内**全自动棘轮循环**,人工只审"上线门禁" | 审上线,不审过程 |
| **L4** | 高度自动 | 多分支并行探索 + 失败库/策略库自积累,人只看晨报 | 只看报告 |
| **L5** | 通用智能组织 | **同一套引擎零改码接入搜/广/推不同域**,甚至迭代"组织代码 program.md" 本身 | 定方向 |

**关键论断:L5 的本质不是更强的模型,而是"迭代能力"与"迭代对象"解耦**——引擎只认 DomainSpec 契约(哪个文件可改、怎么跑评测、看什么指标),换域=换一个目录。就像自动驾驶的"驾驶能力"与"开去哪"解耦。

### 3.1 "智能组织"与单 agent 的区别

autoresearch 默认单 agent 单循环(81 个 agent 是开多个进程)。AlgoPilot 把"组织"显式化:

- **研究员**(Research):读台账(elite+失败库+策略库)→ 产出假设(idea/依据/预期收益/风险)
- **工程师**(Engineer):假设 → 代码 patch(单文件内)
- **评审员**(Review):护栏审查(没碰冻结文件?改动可审查?)+ 统计判定(提升是否超过噪声)
- **台账**(Ledger):append-only 实验日志,一切决策可重建(继承 2.0"日志即真相")
- **晨报**(Morning Report):人只读这一份文档

MVP 阶段这些"角色"是同一个循环里的三个 prompt/三段逻辑;L4 阶段升级为并行多分支 + 角色独立上下文。**组织结构先于并行度**——先有可分工的接口,再谈多 agent。

## 五、风险与诚实的边界

1. **合成数据的定位**:推荐域 MVP 用确定性合成的 CTR 数据(固定 seed、真实因果结构:特征交叉真实有效),目的是验证**循环机制**而非刷新 SOTA。接入真实数据(Criteo/公司数据)只需换 prepare.py——但 prepare.py 属于"人改"的范畴,属于 L2 之外的"装置升级"。
2. **MockLLM 的智能上限**:策略遍历器不是真智能,它的价值是**让闭环零依赖可验证**。真收益要等接真 LLM(用户已有 DeepSeek/智谱 key)。
3. **离线≠在线**:autoresearch 也只对离线指标负责。L3 之前的一切"提升"都是离线代理指标,上线门禁永远在人类手里(L3 的定义本身就是这个边界)。
4. **评测规模**:MVP 数据 2 万样本,依然偏小。但"固定预算+方差自适应判定+elite 复验"这套机制是规模无关的,数据变大机制不变。

## 六、理念升级 v0.2:端到端对齐最终交付(2026-11-14 增补)

初版调研照搬 autoresearch 时埋着一个未言明的假设:val_bpb ≈ 交付。对 LM 训练
成立,对搜广推**不成立**——AUC 是代理,业务结果是交付,两者之间的 gap
(离线在线一致性)是行业最贵的学费。据此 AlgoPilot 升级为三道关体系:

```
离线棘轮(走得快)──► 交付门禁(走得对)──► 上线门禁(人类定边界)
```

- **装置**:新增冻结的 `delivery.py`(端到端会话仿真):模型在固定货架(300 候选)
  上自选曝光(top-8),曝光按 `prepare.true_logit` 的**真实因果 pCTR** 产生点击——
  曝光分布由模型自选(selection bias 天然存在),钻离线空子/制造马太效应的模型在此现形;
- **契约**:`DeliverySpec`(交付主指标不回退 + 生态护栏:曝光熵/冷启用户 CTR);
  新判定 `rejected_by_delivery`;`model_state` 契约保证离线评测与端到端仿真
  用逐位相同的模型;
- **组织记忆**:每次保留记录**兑现率**(offline Δ / delivery Δ)。实测谱系:
  特征交叉 3.07 / 收敛加速 0.86 / 加轮数 0.078——同样是离线保留事件,
  交付价值差 40 倍。研究员的观察上下文携带对齐历史,"对齐最终交付"
  从口号变成可优化的信号;
- **诚实边界**:低容量模型 + 同分布合成数据下,离在线背离偏小(heat-boost
  试探的拦截证据在台账:曝光熵 0.68→0.53 跌破护栏,但离线 AUC 未过棘轮);
  真实数据 + 高容量模型下拦截案例会自然出现。

一句话:**autoresearch 教会我们走得快(棘轮),搜广推教会我们走得对(对齐),
AlgoPilot 把两件事放进同一个组织。**
