# AlgoPilot 理念:像自动驾驶一样的智能组织通用迭代能力

> 本文回答四个问题:为什么要"自动驾驶等级"?什么是"智能组织"?"通用"指什么?
> 以及最重要的一条:**为什么必须端到端对齐最终交付?**

## 〇、第一理念:端到端对齐最终交付(v0.2 起)

autoresearch 有一个隐含的幸运:`val_bpb` 本身就是交付(LM 训练,离线指标≈交付)。
搜广推没有这份幸运——**AUC 是代理,业务结果才是交付**,而两者之间的 gap 是行业
最贵的学费:selection bias、马太效应、代理指标过拟合,在离线指标上全部隐形。

因此 AlgoPilot 的迭代走**三道关**,缺一不可:

```
离线棘轮(秒级,高吞吐)──► 交付门禁(端到端会话仿真)──► 上线门禁(永远在人类手里)
      走得快                    走得对                     定边界
```

- **离线棘轮**回答"有没有变得更好排"(AUC ↑);
- **交付门禁**回答"放进真实管线后,业务结果有没有变得更好"(会话级仿真:
  模型自选曝光 → 按 prepare.true_logit 的**真实因果 pCTR** 产生点击 →
  交付指标不回退 + 生态护栏[曝光熵/冷启用户 CTR]不破才算保留);
- **上线门禁**永远在人类手里——这是 L3 的定义,不是实现限制。

配套的组织机制是**兑现率(alignment ratio)**:每次保留都记录
`offline Δ / delivery Δ`,历史兑现率成为研究员的指南针——
优先提出历史上兑现率高的方向,警惕"离线涨交付不涨"的路。

实测已经给出教科书级的案例(见晨报):特征交叉离线 +0.021、交付 +0.064,
兑现率 **3.07**;而"多训一倍轮数"离线 +0.008,交付只有 +0.0006,兑现率 **0.078**
——**同样是离线保留事件,交付价值差了 40 倍**。没有端到端对齐,组织会
把力气持续花在兑现率 0.078 的方向上。

诚实边界:低容量线性模型 + 同分布合成数据下,离在线背离天然偏小;
交付门禁的"拦截案例"需要高容量模型或真实分布偏移才会自然出现
(roadmap:真实数据接入后)。机制本身由测试保证。

## 一、算法迭代的自动驾驶等级 L0-L5

把自动驾驶分级移植到搜广推算法迭代,每一级都有明确的**人类角色边界**:

| 等级 | 类比 | 机器做什么 | 人做什么 | AlgoPilot 现状 |
|---|---|---|---|---|
| L0 | 徒手 | 无 | 全部(改码/评测/写报告) | 行业界常态 |
| L1 | 定速巡航 | 自动评测、报表 | 改代码、定方向 | `status`/`report` 命令 |
| L2 | 辅助驾驶 | 提假设、写 patch、跑评测 | **审每个 patch** | 支持(台账里逐条看 knobs/diff) |
| L3 | 有条件自动 | **离线装置内全自动棘轮循环** | 只审"上线门禁"与晨报 | **当前默认**(`--level L3`) |
| L4 | 高度自动 | 多分支并行(分叉点结算、最优者合并)、elite 复验、自积累策略库 | 只读晨报 | **已达成首批能力**(`--level L4`,workers=2) |
| L5 | 通用 | 同一引擎零改码接入搜/广/推,甚至**提案修改 program.md 自身**(受限:提案自动化、生效人审、铁律区禁触) | 定方向、批提案 | **前奏已达成**(`pilot propose/approve`) |

两个关键论断:

**1. 等级的本质是人类角色的重新分配,不是模型能力的炫耀。**
L3 的定义本身就是边界:一切离线代理指标上的"提升",上线门禁永远在人类手里。
autoresearch 的 5 分钟固定预算 + 单一 val_bpb,与我们的 90 秒预算 + 单一 AUC,
都是同一种设计:先造一个**不可博弈的仪表盘**,自动驾驶才敢上路。

**2. L5 的本质是"迭代能力"与"迭代对象"解耦。**
自动驾驶的"驾驶能力"与"开去哪"解耦;AlgoPilot 的"迭代能力"(pilot/ 引擎)
与"迭代对象"(domains/*)通过 DomainSpec 契约解耦:
引擎只认四个问题——哪个文件可改、怎么跑评测、看什么指标、护栏是什么。

## 二、"智能组织"与"单个 agent"的区别

autoresearch 默认单 agent 单循环(开 81 个进程是并行,不是组织)。AlgoPilot 把
**组织**显式化——不是更多 agent,而是**可分工的角色 + 不可抵赖的账本**:

| 组织要素 | 实现 | 为什么必须是组织而非单体 |
|---|---|---|
| 研究员 | LLM,读台账出假设(单一变量原则) | 探索方向需要"想法",但想法必须接受审计 |
| 工程师 | LLM,假设→patch(set_knobs / rewrite) | 动手的人不应自己验收自己 |
| 评审员 | **纯代码**,护栏审查+棘轮判定 | 铁面无私的部分永远不交给模型 |
| 台账 | experiments.jsonl 追加式,唯一事实源 | 决策可重建,甩锅有据可查(继承 2.0"日志即真相") |
| 策略库/失败库 | kept/rejected 自动沉淀 | 失败是组织的记忆,不是个人的教训 |
| 晨报 | morning_report.md | 人类唯一出口,L3 的授权边界 |

**组织的第一性原理:角色的产出物互相审计。** 研究员的假设写在台账里,工程师的
diff 被评审员检查,评审员的判定依据写死在契约里,晨报被人类读。MVP 阶段这些角色
是同一循环里的三段逻辑,但接口先于并行度——L4 要做的只是让角色各自拥有独立
上下文与并发。

## 三、为什么从搜广推切入

1. **搜广推是天然的棘轮场景**:日常迭代就是"改特征/损失/采样/结构→看离线指标"
   的高频循环,与 autoresearch 的"改 train.py→看 val_bpb"同构;
2. **评测装置已经存在**:AUC/NDCG/eCPM + 护栏(时延/生态指标)是行业标准,
   不需要发明新评价体系;
3. **行业验证**:Google 2026-07 已公开推荐系统 Agent 自进化系统(离线 Agent
   内循环 + 在线验证闭环),国内团队也在 2026-10 从 autoresearch 出发搭建了
   企业级算法自进化系统(见调研报告 §2.2)——这个方向正当其时,而开源侧
   还没有搜广推域的 autoresearch。AlgoPilot 补的就是这个空位。

## 四、诚实的边界

- **合成数据的定位**:rec 域用确定性合成 CTR 数据验证**循环机制**,不声称刷新
  SOTA;接真实数据 = 换 prepare.py(人类的"装置升级"职责);
- **MockLLM 的定位**:策略遍历器不是智能,它的价值是让闭环零依赖可验证、可测试;
- **离线≠在线**:L3 之前的一切"提升"都是离线代理指标;
- **评测规模**:2 万样本偏小,但"固定预算+方差自适应+复验"机制与规模无关。
